# Tier-1 NOC Incident Triage & Escalation Runbook (SOP)

Standard Operating Procedure for on-duty Tier-1 Network Operations Center (NOC) operators handling `P1`–`P3` alerts generated by `noc_monitor.py`.

---

## 1. First-Response SLA & Acknowledgment (`<= 5 Minutes` for P1)

1. **Check Active Queue & Parent Dependency:**
   ```bash
   python3 -m src.noc_monitor --db ./noc_state.db status
   ```
   * Verify whether downstream alerts are marked `SUPPRESSED_BY_PARENT`.
   * **Never open duplicate tickets** for suppressed child services when `lan-default-gw` or the primary WAN router is `DOWN`.
2. **Acknowledge the Root-Cause Incident Immediately (Records MTTA):**
   ```bash
   python3 -m src.noc_monitor --db ./noc_state.db ack \
     --incident-id <ID> \
     --operator <YOUR_HANDLE> \
     --note "Tier-1 triage started: running MTR and interface checks"
   ```

---

## 2. Tier-1 Linux Diagnostic Checklist

### Case A: Local Gateway or WAN ICMP Loss / High Latency
```bash
# 1. Verify local routing table and physical link carrier state
ip route show default
ip -s link show

# 2. Run 20-cycle bidirectional path trace (identifies exact hop dropping packets)
mtr -rwzc 20 1.1.1.1
```
* **Hop 1 Loss:** Local LAN switch, patch cord, or CPE router fault -> Check onsite CPE power/optical LOS LED.
* **Hop 2–4 Loss:** ISP access/aggregation issue -> Open **ISP Carrier Trouble Ticket (TT)** with `mtr` output attached.
* **Final Hop Only:** Destination service rate-limiting ICMP or upstream outage -> Verify via TCP/TLS port check.

### Case B: Encrypted DNS (`TCP/853`) or HTTPS (`TCP/443`) Degraded / Certificate Warning
```bash
# Inspect live TLS handshake, cipher suite, and X.509 expiration dates
openssl s_client -connect 9.9.9.9:853 -servername dns.quad9.net </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -dates
```
* If `cert_days_left < 14`: Assign `P2` renewal ticket to Systems/PKI Engineer before certificate expiration causes hard outage.

---

## 3. ISP Carrier Trouble Ticket (TT) Escalation Template

When escalating WAN fiber cuts, BGP session drops, or persistent packet loss (`>= 10%`) to an upstream ISP carrier, include all fields below:

```text
[NOC ESCALATION - SEVERITY P1/P2]
- Circuit ID / Service ID : [INSERT_CIRCUIT_ID]
- Site Name & Location    : [INSERT_SITE_NAME]
- Outage Start Time (UTC) : [YYYY-MM-DD HH:MM UTC]
- Observed Symptom        : [Hard Down / Packet Loss XX% / High RTT XX ms]
- CPE / ONU LED Status    : [PON: OFF | LOS: RED BLINKING | PWR: GREEN]
- Onsite Contact & Phone  : [NAME / PHONE FOR FIELD TECH ACCESS]
- Attached Diagnostics    : [Paste 20-packet mtr -rwzc output]
```

---

## 4. End-of-Shift Handover Procedure

Fifteen minutes prior to shift change (`08:00`, `16:00`, `00:00`), generate the live Markdown handover report and brief the incoming operator on all `OPEN` and `ACKNOWLEDGED` incidents:

```bash
python3 -m src.noc_monitor --db ./noc_state.db handover --shift "Day Shift (08:00-16:00)"
```
